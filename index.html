How QuickPDF works

QuickPDF is a collection of seven PDF utilities that run entirely inside your web browser. When you choose a file, it is read locally by JavaScript using the File API. All the work — parsing, merging, rendering, OCR — happens on your device. Nothing is transmitted to a server, because there is no server.

This matters for two reasons. First, privacy: sensitive documents like contracts, medical records, and IDs never leave your computer. Second, security: there is no database to breach, no log of what you uploaded, and no account to compromise.

QuickPDF is built on trusted open-source libraries. PDF parsing and manipulation use pdf-lib. PDF rendering and text extraction use pdfjs-dist from Mozilla. OCR uses Tesseract.js, the WebAssembly build of Google's Tesseract engine. All three have been audited and widely deployed.

Known limits

Client-side processing is not the same as desktop software. Compression in QuickPDF redraws each page as a JPEG rather than re-encoding the original content streams, so text in a compressed PDF is no longer selectable. OCR is English-only in this version and its accuracy depends heavily on scan quality. Very large PDFs (over roughly 100 MB) may exhaust a phone's available memory. Password-protected PDFs are rejected deliberately — handling passwords would mean handling encryption keys, which is not something we want to do in a browser tab.

Frequently asked questions

Are my files uploaded anywhere?

No. All processing happens in your browser using JavaScript and WebAssembly. You can verify this by opening your browser's developer tools, switching to the Network tab, and using any tool — you will see no requests carrying your file's contents.

Is QuickPDF really free?

Yes, with no accounts, no watermark, and no file limits imposed by us. The only limits are what your browser can handle.

Can I use QuickPDF offline?

Yes. After your first visit, the application shell is cached by a service worker, so the tools open even without a network connection. OCR needs to download English language data on first use, after which it is cached too.

Why does compression look different from Adobe Acrobat?

Acrobat uses decades of tuned heuristics and Ghostscript-based re-encoding. QuickPDF uses a browser-friendly approach: rasterise each page to a JPEG and rebuild the PDF. The result is usually smaller but loses text selectability. We state this clearly on the compression page so you can choose deliberately.

Which browsers are supported?

Any modern browser: Chrome, Edge, Safari, Firefox, and their mobile versions. WebAssembly is required for OCR; everything else works without it.
